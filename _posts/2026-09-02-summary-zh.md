## [1.5 小时训练的小型 Transformer 击败众多 LLM](https://mvakde.github.io/blog/44-on-arc-1/) ⭐️ 8.0/10

一位开发者从零开始仅用 1.5 小时在 ARC 谜题上训练了一个小型自回归 Transformer，其结果可与许多更大的 LLM 竞争，甚至超越它们。该项目明确表明，无需依赖大规模语言模型也能应对复杂的推理基准测试。 这之所以重要，是因为它挑战了“顶尖推理能力需要巨大模型规模和训练预算”的普遍假设。它表明，以样本效率和架构优化为重点的方法可以降低 AI 推理研究的成本，并让更多人参与其中。 作者澄清，这不是 LLM，而是一个小型自回归 Transformer；ARC 是一个元学习基准，从评估谜题中学习是合理的，因为从未使用过标签。分数提升主要来自现代架构选择（如 SwiGLU 和 RMSNorm）、更好的数据多样性与打乱方式，以及层数从 4 层扩展到 8 层。

hackernews · porridgeraisin · 9月1日 09:52 · [社区讨论](https://news.ycombinator.com/item?id=49519939)

**背景**: ARC-AGI-1（抽象与推理语料库）由 François Chollet 于 2019 年提出，用于衡量 AI 系统应对未经准备的新颖推理问题的能力。样本效率指的是系统达到熟练水平所需的数据量；人类能从相对较少的例子中学习，而模型通常需要多几个数量级的数据。这个项目展示了一条替代路径：通过精心的架构和训练选择，在具有挑战性的推理基准上大幅降低数据和算力需求。

## [Firefox 对浏览器引擎多样性仍然至关重要](https://www.newsonaut.com/articles/hang-on-to-your-firefox) ⭐️ 7.0/10

Newsonaut 的一篇评论文章认为，尽管 Mozilla 有过失，Firefox 仍然是浏览器引擎多样性与竞争的关键。文章在 Hacker News 上的评论区围绕广告拦截、Mozilla 的取舍以及浏览器单一文化的风险展开了实质性讨论。 Firefox 是唯一非 Chrome 且非 WebKit 的主流浏览器，因此它的存亡直接决定 Web 是否能保持多引擎生态。如果 Firefox 消失，Web 开发者和用户将失去制衡 Chromium 主导地位的重要力量，这可能削弱 Web 标准并减少用户的选择。 评论者指出，Chrome 的分支不能算作独立浏览器，因为它们共用同一引擎且很难与上游分道扬镳。还有人强调 Firefox 可以使用高质量的广告拦截工具；一位用户还分享了一个替代 WPT 测试结果查看器，展示 Servo、Ladybird 等替代引擎的进展。

hackernews · speckx · 9月1日 20:30 · [社区讨论](https://news.ycombinator.com/item?id=49527748)

**背景**: 如今大多数主流浏览器只基于少数几个引擎：Chromium 的 Blink（Chrome、Edge、Brave、Opera）和 WebKit（Safari）。Firefox 使用自己的 Gecko 引擎，是维持 Web 开放与互操作性的最后几个有意义的选择之一。浏览器引擎多样性之所以重要，是因为标准需要靠真实实现来检验，单一引擎主导会潜移默化地决定 Web 开发者能做什么、不能做什么。Web Platform Tests（WPT）测试套件用于衡量各引擎符合标准的程度。

**社区讨论**: 评论整体上支持文章观点，但也直言批评 Mozilla，用户提到其收购广告技术公司、收集数据以及用 Firefox 推送个性化广告等“反特性”正在赶走用户。然而，多位评论者仍同意 Firefox 是引擎多样性的最后希望，还有人认为它是唯一拥有高质量广告拦截工具的浏览器。评论区还讨论了开发者对 Web 现状的责任，因为多数人只在 Chromium 上测试，这加剧了单一文化。

## [iOS 版 Firefox 内置广告拦截功能上线](https://blog.mozilla.org/en/firefox/ad-blocker-on-ios/) ⭐️ 7.0/10

Mozilla 已开始为 iOS 版 Firefox 逐步推出实验性的内置广告拦截功能，但该功能尚未全面开放。目前它仅作为受控实验，向部分用户分阶段启用。 这是 Mozilla 在苹果平台上将隐私功能直接集成到 Firefox 中的重要一步，因为 iOS 上所有浏览器都必须使用 WebKit。由于推广范围有限且要求开启遥测，其近期影响不大，用户可能仍会依赖第三方拦截器或替代浏览器。 该广告拦截功能使用 WebKit 的原生内容拦截 API，因为 iOS 版 Firefox 基于 WebKit 构建。它会拦截网页上的广告，但不会过滤搜索引擎结果页中的广告，这一限制遭到了用户批评。

hackernews · HieronymusBosch · 9月1日 13:46 · [社区讨论](https://news.ycombinator.com/item?id=49521973)

**背景**: iOS 限制所有第三方浏览器使用 Apple 的 WebKit 引擎，并通过原生扩展 API 支持内容拦截，该 API 采用基于 JSON 的规则来隐藏或阻止页面元素。因此，iOS 版 Firefox 依赖 WebKit，与桌面版 Firefox 中常见的广告拦截扩展不同，iOS 版必须使用 WebKit 的内容拦截 API 将该项功能直接内置于浏览器中。这个实验性功能在 Firefox 设置中增加了一个集成开关，而无需安装单独的拦截应用。

## [第九巡回法院裁决 Perplexity 诉亚马逊，或将重塑 AI 电商](https://www.reddit.com/r/ecommerce/comments/1w436w4/the_ninth_circuits_perplexity_vs_amazon_ruling/) ⭐️ 7.0/10

第九巡回上诉法院推翻了此前禁止 Perplexity 的 Comet 浏览器代用户在亚马逊购物的禁令，裁定当用户指示代理时，访问亚马逊服务器的是用户而非 Perplexity。这削弱了依据《计算机欺诈与滥用法》（CFAA）对 AI 购物代理提起的诉讼。 该裁决使得亚马逊和其他平台更难通过计算机欺诈诉讼来阻止 AI 购物代理，使竞争焦点转向技术协议与信任机制。电商卖家需要适应由代理中介购物、且声明数据须可验证的新环境。 法院的理由是 Comet 仅在用户指示下行动，因此法律上的访问主体是用户而非 Perplexity。作者重点提到三种新兴方案——OpenAI/Stripe 的作用域单次使用支付令牌、Google AP2 的授权凭证、以及 Shopify UCP 的通用目录语言——并指出尚未解决的信任问题在于，卖家关于库存、履约或发货的声明能否被独立验证。

reddit · r/ecommerce · /u/PuzzledBag931 · 9月1日 05:58

**背景**: 《计算机欺诈与滥用法》（CFAA）禁止未经授权访问受保护的计算机，亚马逊等平台曾主张 AI 代理访问其网站即构成违法。在 2021 年 Van Buren 诉美国案中，最高法院收窄了“超出授权访问”的认定范围，为“用户授权代理即视为授权访问”提供了更强依据。与此同时，OpenAI 的委托支付规范和 Stripe 的共享一次性令牌等协议正在涌现，使代理无需暴露卡号即可完成交易。

## [利用公开海关记录核验供应商，省时又省钱](https://www.reddit.com/r/ecommerce/comments/1w4csvt/i_wasted_most_of_my_first_year_sourcing_because_i/) ⭐️ 6.0/10

一位 Reddit 用户分享说，他们在第一年通过名录网站和冷邮件找供应商，浪费了大量时间，还因一家伪装成工厂的贸易公司损失了定金，之后才发现许多国家会公开海关记录。这些记录让他们看到谁实际向谁发了什么货，把供应商核验从“基于信任的问答”变成“基于证据的比对”。 这个技巧对进口商和电商卖家有重要意义，因为它提供了一种具体且公开可查的核验方式，可在支付定金前验证供应商，从而省钱并降低欺诈风险。它让采购更高效、更客观，并且在许多公开海关数据的国家都适用。 公开海关数据可从多种渠道获取，包括美国 CBP 公共数据门户（CBP Public Data Portal）以及 Port Examiner、ImportGenius 等商业平台。记录通常显示发货人、收货人、货物描述和发货频率，可与供应商在电话沟通中所说的内容进行比对。

reddit · r/ecommerce · /u/Silly\_Captain2089 · 9月1日 13:59

**背景**: 每次集装箱跨境时都会产生海关记录，而在许多国家这些记录是公开可查的。数据中包含提单详情，列出交易双方、货物和运输路线，让进口商得以看到一家公司多年的实际出货历史。通过查看这些记录，进口商可以判断一家公司究竟是真正的工厂还是中间贸易商，从而把供应商核验变成基于证据的流程，而不是信任游戏。
